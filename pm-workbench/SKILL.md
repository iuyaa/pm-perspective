# 产品工作台

把用户当前的问题推进到可用的决策或产物。专业方法来自四个完整保留的上游库，通过文件读取按需执行。

## 工作方式

1. 复用用户给出的材料和已确认决定，识别当前目标、业务场景、交付物和深度。已有文档先读当前版本。简单任务直接完成。
2. 对非平凡需求，简短审视真实目标、问题根因、未经验证的假设及上下游影响。比较局部改进、系统优化和问题重构，推荐与当前范围相符的路径。已有明确决定时尊重决定。
3. 在下面的表中选择最贴近当前交付物的一条路线，只读对应参考文件。按其中路径读取一个主技能，再按真实依赖加载辅助技能或模板。每完成一个阶段，才判断下一阶段是否必要。
4. 运用主技能的方法完成任务。原库内部提及另一技能时，先判断当前任务是否需要，再通过来源 ID 和路径定位。读过的文件复用上下文。
5. 核对结果是否满足目标、交付形式和已确认范围。正文交付实际结果，重要假设、未决事项及证据缺口随结果列明。

| 当前任务 | 按需读取 |
| --- | --- |
| 内部后台、HR/招聘、审批、权限、跨系统、数据迁移的需求、PRD 或产品视角 RFC 评审 | [platform.md](references/platform.md) |
| 访谈、用户问题、JTBD、需求证据、机会与方案探索 | [discovery.md](references/discovery.md) |
| 优先级、路线图、商业论证、市场、竞争、定位和定价 | [strategy.md](references/strategy.md) |
| 通用 PRD、AI 产品需求、用户故事、验收、发布及干系人沟通 | [delivery.md](references/delivery.md) |
| 指标、报表口径、埋点、实验、上线结果与复盘 | [measurement.md](references/measurement.md) |
| 用户指定某个原技能，或上述路线覆盖不足 | [library.md](references/library.md)，定向检索完整索引 |

内部业务系统默认优先走平台路线。市场化产品按实际目标选择探索、策略或交付路线。跨场景任务从当前最关键的决定开始，保留同一需求的证据和决定供后续阶段复用。

## 统一协作约定

- 默认中文，沿用用户已有文档语言和团队模板。用户要求的段落修改只调整指定内容。
- 能用会话中已有信息完成的，立即交付。仅对影响业务结果、当前范围或授权的关键缺口提问，其余采用可逆假设并明确标注。业务状态、金额、审批权限等关键语义有缺口时，先完成可确定部分并列出待决项。
- 文档长度随任务复杂度调整。PRD 应写清用户可见行为、职责、条件和可验证结果。工程实现由相应任务承接。模型输出类功能补充行为评估和通过标准。
- 把事实、用户决定、建议和假设区分清楚。访谈、数据、完成状态和市场数字均需证据。评审意见定位到具体材料与业务后果，保留材料不可读带来的不确定性。
- 本入口负责协作流程。上游中的首次安装、私人配置、持久记忆、自动建档、开新会话、切换模型、插件安装和固定逐阶段确认属于可选宿主流程，仅在用户明确要求相应功能时采用。专业方法、校验要求和实际执行依赖仍须遵守。
- 原库技能在当前会话内作为参考执行。子 Agent 协作仅在用户或适用项目指令授权时使用。外部写入按当前任务的授权处理。
- 产物默认在对话中交付，用户要求文件时遵从其位置和格式。涉及 PagePrd 原型及说明、JR Design 视觉、Word/PPT/表格等专门产物时，衔接当前环境对应技能，并提供已确认的需求与验收口径。

## 定位专业文件

当前技能目录内的 [library.json](references/library.json) 定义相对该配置文件的资料库根目录和四个来源版本。路由文件中的路径均相对该根目录。先以配置文件所在目录解析相对根目录，再打开指定 `METHOD.md`，其内部相对链接以该文件所在目录为基准解析。仓库根目录的 `references/`、`agents/`、模板及脚本也保留在原位置。

完整索引数量随上游同步更新。需要补充检索时按来源或关键词搜索 [catalog.tsv](references/catalog.tsv)，只读取匹配行。索引用于定位，执行前阅读实际技能。缺失文件时报告具体路径，利用可读资料继续完成可确定部分。
